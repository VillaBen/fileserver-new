## 一、版本管理策略

### 1.1 Git 工作流程

本项目采用简化的 Git 工作流程，确保所有变更都有迹可循：

```
main (主分支)
  └── feature/* (功能分支，可选)
  └── bugfix/* (修复分支，可选)
```

### 1.2 提交规范

#### 提交信息格式

```
&lt;type&gt;: &lt;subject&gt;

&lt;body&gt; (可选)
```

#### Type 类型

| 类型 | 说明 |
|------|------|
| `feat` | 新功能 |
| `fix` | 修复 Bug |
| `docs` | 文档更新 |
| `style` | 代码格式调整（不影响代码逻辑） |
| `refactor` | 重构 |
| `test` | 测试相关 |
| `chore` | 构建/工具链相关 |

#### 示例

```
feat: 新增文件分享功能
fix: 修复回收站恢复文件冲突检测
docs: 更新 API 文档
```

### 1.3 分支策略

| 分支名 | 用途 | 说明 |
|--------|------|------|
| `main` | 主分支 | 保持稳定，所有发布版本 |
| `feature/*` | 功能分支 | 新功能开发，完成后合并到 main |
| `bugfix/*` | 修复分支 | Bug 修复，完成后合并到 main |

## 二、破坏性操作审批流程

### 2.1 破坏性操作定义

**破坏性操作** 包括但不限于：

- ❌ 删除文件（包括文档、代码、配置等）
- ❌ 删除目录
- ❌ 重命名文件/目录（可能影响引用）
- ❌ 清空数据库
- ❌ 清空上传文件目录
- ❌ 重置环境配置
- ❌ 撤销 Git 提交（git reset --hard 等）

### 2.2 操作审批流程

#### 步骤 1: 操作前确认

在执行任何破坏性操作 **前**，必须：

1. **明确说明** 要执行什么操作
2. **解释原因** 为什么需要执行该操作
3. **列出影响范围** 哪些文件/功能会受影响
4. **提供备选方案** 是否有其他更安全的方式

#### 步骤 2: 用户审批

必须等待用户明确确认后才能执行，确认方式包括：

- ✅ "可以执行"
- ✅ "确认删除"
- ✅ "好的，执行吧"

**禁止** 在没有用户明确确认的情况下执行任何破坏性操作。

#### 步骤 3: 备份（可选但推荐）

对于重要操作，建议先进行备份：

```bash
# 备份文件/目录
cp -r path/to/file path/to/file.backup.$(date +%Y%m%d_%H%M%S)

# Git 备份（如果已初始化）
git add .
git commit -m "backup before deletion"
```

#### 步骤 4: 执行操作

只有在获得用户明确确认后，才执行操作。

#### 步骤 5: 验证结果

操作完成后，验证：

- 操作是否按预期完成
- 没有意外的副作用
- 系统功能仍然正常

### 2.3 安全操作清单

执行操作前，请确认：

- [ ] 我已经明确说明了要执行的操作
- [ ] 我已经解释了操作原因
- [ ] 我已经列出了影响范围
- [ ] 我已经获得了用户的明确确认
- [ ] 我已经考虑了备份（如需要）
- [ ] 我已经验证操作结果

## 三、文档版本管理

### 3.1 文档版本号规则

采用语义化版本号：`v{主版本}.{次版本}.{修订号}`

| 版本段 | 说明 |
|--------|------|
| 主版本 | 重大结构变更、不兼容的修改 |
| 次版本 | 新功能、内容扩充 |
| 修订号 | Bug 修复、小的调整 |

### 3.2 文档变更历史

每个文档应在末尾包含变更历史：

```markdown
---

**文档版本**: v1.1  
**最后更新**: 2026-06-05  
**变更记录**:
- v1.1 (2026-06-05): 添加安全章节
- v1.0 (2026-06-04): 初始版本
```

## 四、Git 使用指南

### 4.1 常用命令

#### 查看状态

```bash
# 查看当前状态
git status

# 查看变更差异
git diff
```

#### 提交变更

```bash
# 添加所有变更
git add .

# 提交
git commit -m "feat: 描述你的变更"
```

#### 查看历史

```bash
# 查看提交历史
git log

# 查看简洁历史
git log --oneline
```

#### 撤销操作（安全）

```bash
# 撤销工作区变更（未 add）
git checkout -- &lt;file&gt;

# 撤销暂存（已 add 未 commit）
git reset HEAD &lt;file&gt;
```

#### 危险操作（⚠️ 需审批）

```bash
# ⚠️ 这些操作需要用户确认！
git reset --hard    # 重置提交
git rebase          # 变基
git push -f         # 强制推送
git clean -f        # 清理未追踪文件
```

### 4.2 Git 标签（版本发布）

```bash
# 创建标签
git tag -a v1.0.0 -m "Version 1.0.0"

# 查看标签
git tag
```

## 五、应急恢复流程

### 5.1 文件误删除恢复

如果不小心删除了文件：

#### 方案 1: Git 恢复（如果已提交）

```bash
# 恢复已删除但已提交的文件
git checkout HEAD -- &lt;path/to/file&gt;
```

#### 方案 2: 从备份恢复

如果有备份文件：

```bash
# 恢复备份
cp path/to/backup path/to/original
```

### 5.2 紧急联系

如果发生意外的破坏性操作：

1. **立即停止** 任何进一步操作
2. **不要** 清空回收站/临时文件
3. **联系负责人** 寻求帮助
4. **记录** 发生了什么操作
